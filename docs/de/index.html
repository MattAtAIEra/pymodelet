Die Philosophie

Der umgekehrte Kompromiss zur ORM-Welle

2006 verlangte Hibernate, HQL, Session-Lebenszyklen und Mapping-Rituale zu lernen, bevor man eine einzige produktive Zeile schrieb. Modelet macht es umgekehrt: SQL respektieren und nur den mühsamen Teil übernehmen.

SQL → object

Abfragen → SQL

SELECTs schreibst du in dem ANSI-SQL, das du schon kennst — Subqueries und Joins inklusive. Das Framework trägt jede Zeile nur in ein Objekt zurück. Keine neue Abfragesprache.

object → SQL

Schreiben → Framework

Mechanisch und fehleranfällig ist das Auflisten der Spalten für INSERT / UPDATE / DELETE. Modelet erzeugt sie aus dem TxnMode-Zustand der Entität, schreibt den Schlüssel zurück und setzt Audit-Felder.

Für Skalierung gebaut

Tiefe Paginierung ohne Speicherlast

Ob das Resultset 100 oder 500.000 Zeilen hat — nur die Zeilen der angeforderten Seite werden zu Entitäten. Die allerletzte Seite zu erreichen lädt nie das gesamte Set in deine Anwendung.

500,000

LIMIT / OFFSET wird in die Datenbank verlagert; die Anwendungsschicht bildet nur seitengroße Zeilen ab. Speicher- und Mapping-Kosten bleiben konstant — O(Seite), nicht O(gesamt) — von Seite 1 bis Seite 50.000. Der alte Ansatz, alles in den Speicher zu laden, ist Geschichte.

Der Ablauf

Von SQL zur Entität und zurück — automatisch

Schreibe SQL, erhalte eine Liste von Entitäten. Ein Web-Formular bindet Nutzereingaben per Expression Language in die Entität. Die Mittelschicht ruft nur saveOrUpdate auf derselben Entität auf — Modelet macht daraus wieder SQL.

ANSI-SQL schreiben

Die Abfrage gehört dir — Joins, Subqueries, Window Functions. Keine DSL steht zwischen dir und der Datenbank.

Zeilen werden Objekte

model.find(sql, params, Book) trägt jede Zeile in eine typisierte Entität. Spaltennamen werden automatisch auf Felder abgebildet.

Die Entität ändert sich

Ein Formular oder ein Service verändert dasselbe Objekt; sein TxnMode merkt sich, ob es neu, geändert oder zum Löschen bestimmt ist.

Objekte werden SQL

model.save(entity) erzeugt INSERT / UPDATE / DELETE, schreibt den generierten Schlüssel zurück und setzt Audit-Felder.

Entitäten werden mit JPA-kompatiblen Annotationen deklariert — @Table @Id @Column @Transient @Enumerated @GeneratedValue — und lesen sich wie jede Jakarta-Persistence-Entität. Geliehen ist nur das Vokabular; die Engine bleibt SQL-first.

Schnellstart

Ein Beispiel, von Anfang bis Ende

Ein klassisches One-to-Many: Ein Author hat viele Books. Der Fremdschlüssel ist die Beziehung — kein @OneToMany, kein Lazy Loading.

1Entitäten mit JPA-kompatiblen Annotationen definieren

models.pyPython 3.10+
@Table("author")
@dataclass
class Author(Entity):
    name: str | None = None

@Table("book")
@dataclass
class Book(Entity):
    author_id: int | None = None          # FK = the relationship
    title: str | None = Column("bookName")
    price: Decimal | None = None

2Mit dem SQL abfragen, das du kennst

query.pyfind → list
# plain ANSI SQL in, a list of entities out
books = model.find(
    "select * from book where author_id = ? order by id",
    [author_id], Book)

3saveOrUpdate — das Framework schreibt das SQL

save.pysave
book = Book(author_id=author.id,
            title="pymodelet in Action")
model.save(book)    # new entity → INSERT, id written back

book.price = Decimal("499")
model.save(book)    # loaded entity → UPDATE. same call.

Ursprung · 2006

Eine präzise Entscheidung

„Das ER-Modell und SQL sind das Fundament — Wandel löscht ihren Wert nicht aus.“ Zwei Jahrzehnte später entdeckt die Python-Community „SQL-first“ neu, als wäre es neu. Matt schrieb es 2006 nieder.

Modelet wurde 2006 von Matt geschaffen, um die ORM-Lernkurve zu ebnen und die Auslieferung seines Teams zu beschleunigen. Die ganze Geschichte steht in TRIBUTE.de.md.

Portiert im KI-Zeitalter

Die KI schrieb den Code. Die menschliche Weisheit traf die Entscheidungen.

Diese Python-Portierung wurde 2026 von einer KI getippt — und keine einzige Designentscheidung neu erfunden. Das Muster von 2006 entschied; die KI folgte. Auch eine KI muss den Werten menschlicher Weisheit folgen: Ein bewährtes Entwurfsmuster ist genau das, was weitergegeben werden soll. Die Geschichte dieser Schuld erzählt die Widmung.
